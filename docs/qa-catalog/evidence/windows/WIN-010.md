# WIN-010 | client-windows/ApiClient | 严重 | 缺少超时与重试，错误码处理不完整
- 描述：`ApiClient` 初始化 `HttpClient` 未设置 `Timeout`（默认 100s），超时过长且无调用方可覆盖；重试仅针对 401 且仅一次（`_isRefreshing` 互斥），对 429/500/502/网络闪断无重试；`SendWithAuthRetryAsync` 先 `EnsureSuccessStatusCode()` 再读 `ApiResponse.Code`，HTTP 非2xx 时直接抛异常，业务码 `0/200` 判断在 `AwCollectorService.IsSuccessResponse` 中才生效，二者语义割裂，调用方无法区分 HTTP 错误与业务错误。
- 位置：src/client-windows/Pim.Client.Core/Services/ApiClient.cs:19-28,134-171; src/client-windows/Pim.Client.Core/Services/AwCollectorService.cs:280-282
- 问题：
  ```csharp
  _httpClient = new HttpClient(handler) { BaseAddress = new Uri($"{ClientDefaults.DefaultServerUrl}/api/v1/") }; // 无 Timeout
  response.EnsureSuccessStatusCode(); // HTTP 错误直接抛
  private static bool IsSuccessResponse<T>(ApiResponse<T> result) => result.Code is 0 or 200;
  ```
- 风险：弱网环境下请求挂起 100s 阻塞采集线程； transient 500 无重试导致数据丢失感知为“上传失败”；HTTP 200 + Code!=0 的业务失败与 HTTP 500 异常混为一谈，日志难以定位。
