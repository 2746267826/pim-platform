# WIN-007 | client-windows/配置 | 一般 | 硬编码地址散落且归一化逻辑不一致
- 描述：默认地址硬编码多处：`ClientDefaults.DefaultServerUrl="http://127.0.0.1:5858"`、`AwCollectorService.AwBase="http://127.0.0.1:5600"`、`KeyStatsCollectorService/KeyStatsLocalStatsClient="http://127.0.0.1:18080"`。归一化不一致：`ApiClient.NormalizeServerUrl` 将 `localhost` 转 `127.0.0.1` 并保留原 scheme；`ServerAddress.Normalize` (Shell) 若无 scheme 则强制 `https://` 前缀，二者对同一输入 `localhost:5858` 得到不同结果。
- 位置：src/client-windows/Pim.Client.Core/ClientDefaults.cs:5; src/client-windows/Pim.Client.Core/Services/AwCollectorService.cs:20; src/client-windows/Pim.Client.Core/Services/KeyStatsCollectorService.cs:10-11; src/client-windows/Pim.Client.Core/Services/KeyStatsLocalStatsClient.cs:9-10; src/client-windows/Pim.Client.Core/Services/ApiClient.cs:57-68; src/client-shell-windows/Pim.Shell.App/ServerAddress.cs:5-23
- 问题：
  ```csharp
  public const string DefaultServerUrl = "http://127.0.0.1:5858";
  private static readonly string AwBase = Environment.GetEnvironmentVariable("AW_BASE_URL") ?? "http://127.0.0.1:5600";
  // ApiClient: localhost -> 127.0.0.1
  return uri.Host.Equals("localhost",...) ? new UriBuilder(uri){Host="127.0.0.1"}.Uri.ToString() : trimmed;
  // ServerAddress: 无 scheme -> https://
  trimmed = "https://" + trimmed;
  ```
- 风险：新环境需改多处，易遗漏；同一配置在 Daemon 与 Shell 中表现不一致，导致健康检查与实际 API 调用指向不同地址，增加运维成本。
