并行分轨路线图

完整设计不按开发成本裁剪，但需要用共享核心约束四条轨道：Web 规划闭环、Outlook Graph 同步、端侧 Companion、复盘报告。

附件 HTML 原型保留 核心事实改动必须确认 PIM 品牌统一视觉
推荐

方案 1：共享核心 + 并行产品轨

先定义统一对象模型、确认/审计、安全边界和 API，再让 Web、Outlook、端侧、报告四条轨道并行推进。最符合当前完整蓝图。

备选

方案 2：体验先行 + 后补治理

先把 Today、任务、日历、端侧体验做完整，再补 Outlook、审计和历史回放。视觉反馈快，但核心规则后补风险较高。

备选

方案 3：同步/审计优先

先打牢 Graph 同步、冲突、确认和历史系统，再扩展 UI。数据安全扎实，但用户可见体验会来得较晚。

轨道 A · Web 规划闭环 Today 控制台、日历图层、任务工作台、习惯、数据中心
Today控制台式首页

时间轴 + 任务压力 + AI 建议 + 提醒 + 复盘入口，支持密度切换。

任务领域/项目 + 任务本 + 任务 + checklist

任何任务都可拆为多个执行段，状态包含原因和复盘结果。

时间图层事件、任务段、习惯、时间预算、AI 占位

所有图层可开关，允许只查看部分。

数据中心全局治理 + 专用对象页

全局搜索、审计、回收站、同步批次、批量治理；对象页保留专业管理。

轨道 B · Outlook Graph 同步 ICS 保留，Outlook 使用 Microsoft Graph 双向同步
连接设置 Client ID / Tenant / 权限

使用设备代码连接：打开微软链接输入代码，状态过程完整呈现。

同步Graph 增量同步与来源映射

同步过程展示步骤、deltaLink、批次、冲突、写回队列和失败重试。

来源Outlook 特殊标签

Outlook 日程可单独筛选、批量管理、查看 Graph event id 和来源元数据。

确认冲突人工决策 + 二级确认

双方都改核心字段时不自动覆盖；Outlook 来源操作额外二级确认。

轨道 C · Windows / Android Companion 漂亮端侧壳 + 采集上传 + 通知/审计操作
端侧壳PIM 品牌感

不是纯原生默认控件；视觉语言和 Web 一致，保留平台交互习惯。

通知低风险通知栏/Toast，高手险打开详情

低风险可快捷操作，高风险必须进入审计中心或 Web 审计页。

采集可插拔采集器

Windows/Android 默认保守，未来可扩展设备状态、健康、会议、IDE、文件等。

离线仅缓存采集数据

通知确认、审计、任务/日程改动、复盘输入、Outlook 写回都必须在线。

轨道 D · 复盘 / 报告 / AI 主动助理 AI 可自动生成新产物，但事实改动必须确认
报告日报/周报/月报/项目复盘

报告属于新产物，可自动生成和更新。

偏差计划 vs PC/手机实际活动

用于复盘和建议，不直接覆盖任务/日程事实。

提醒完整提醒中枢

基础提醒、智能提醒、行动按钮、策略、渠道、免打扰、历史和 AI 理由。

确认AI 主动建议但不越权

标题、时间、地点、状态、所属本、重复规则等核心事实数据必须人工确认。

领域对象模型

领域/项目、任务本、任务、执行段、事件、习惯、提醒、报告。
