### PR-2 集中式数据隔离（#205）

- `Pim.Core/Data/IUserOwnedEntity.cs` 标记接口；**39 个**带 UserId 实体全部实现。
- `PimDbContext` 注入 `ICurrentUserService`（可选构造参数），`OnModelCreating` 末尾自动挂
  `e => CurrentUserId == null || (Guid?)e.UserId == CurrentUserId`，与软删过滤 AND 组合（`CombineFilters`）。
- 语义：业务请求强制隔离；**系统上下文（后台 job、启动引导、手工 new DbContext 的既有测试）不过滤**。

- 既有手写 `Where(UserId==...)` 保留作双保险。
- 测试 13 个：反射防护（① 所有接口实体必须挂过滤器 ② 所有映射非空 UserId 列的实体必须实现接口——**新实体漏配直接红**）、逐模块行为矩阵、软删组合、E2E。
- **踩过的坑（合并前已修）**：
  1. 测试命名空间 `Pim.UnitTests.Infrastructure` 会遮蔽生产 `Pim.Infrastructure`（改用 `Pim.UnitTests.DataIsolation`）；

## 6. 环境操作手册（重要，不读必踩坑）

本工作区（Windows + WorkBuddy 沙箱）有以下**硬性环境约束**：

### 6.1 dotnet 本地不可用

沙箱进程树无法解析 Windows 用户目录（`Environment.GetFolderPath` 返回 null），
NuGet 还原必炸：`NuGet.targets error: Value cannot be null. (Parameter 'path1')`。
设 APPDATA/PROGRAMDATA/HOME/NUGET_PACKAGES 均无效，SDK 8/10 都一样。
**→ 后端编译与测试全部依赖 GitHub Actions CI（build-api 跑 `dotnet test Pim.sln`）。**
每次推送预留 ~15 分钟 CI 反馈时间；按 CI 日志修编译错误是正常流程（PR-3 修了三轮）。

### 6.2 git 引用写入不可靠（WorkBuddy 虚拟化）

- `git worktree add` / `git checkout -b` / `git update-ref` 的**分支引用写入会被静默丢弃**（HEAD 文件、索引、对象库正常）。
- **可靠流程**（已在 3 个 PR 验证）：
  ```bash
  git clone https://github.com/2746267826/pim-platform.git C:/pim-wt/<topic>
  cd C:/pim-wt/<topic>
  mkdir -p .git/refs/heads/workbuddy-win
  git rev-parse master > .git/refs/heads/workbuddy-win/<branch>
  echo "ref: refs/heads/workbuddy-win/<branch>" > .git/HEAD
  # 正常编辑、git add、git commit
  # commit 后引用可能未更新，用对象扫描找回提交哈希：
  for obj in $(find .git/objects -type f -not -path "*/pack/*" -newermt "2 minutes ago"); do
    id=$(echo "$obj" | sed 's|.git/objects/||; s|/||')
    [ "$(git cat-file -t "$id" 2>/dev/null)" = "commit" ] && echo "COMMIT: $id"
  done
  echo "<hash>" > .git/refs/heads/workbuddy-win/<branch>
  git push origin <hash>:refs/heads/workbuddy-win/<branch>
  ```
- 推送统一用 `git push origin <commit-hash>:refs/heads/<branch>`（不依赖本地引用状态）。
- 偶发 `Signal: SIGTERM`（命令被环境杀死）——**直接重试即可**，无副作用。
- 主 WorkBuddy worktree（`Worktrees/pim-platform/master-3ba5d75b`）的 git 已损坏，只做文件读取；**所有 git 操作在 `C:/pim-wt/*` 克隆副本进行**。

### 6.3 gh CLI 认证

`gh auth login` 不持久。每个 gh 命令前内联取令牌（需 `dangerouslyDisableSandbox` 提升权限）：

```bash
GH_TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill 2>/dev/null | grep '^password=' | cut -d= -f2) gh <cmd>
```

长命令（如大段 PR 正文）易触发 SIGTERM——正文写文件后用 `gh pr create --body-file x.md`。

### 6.4 前端可本地验证

`npm install`（约 12 分钟）+ `npm --prefix src/client-web run build` 可用，提交前端前务必本地构建。
YAML/JSON 配置用前端 `node_modules/js-yaml` 校验（系统 Python 无 yaml 模块）。

### 6.5 CI 约定（AGENTS.md）

- 分支命名 `{agent}-{os}/{topic}`；本系列用 `workbuddy-win/*`。
- PR 描述必须含四个双语段落（技术修改 / 功能变化 / 如何体验 / 测试），否则 Release changelog 退化。
- 合并用 squash；合并后删远程分支、删本地克隆。
- CI 全绿才算完成；仅文档变更不触发平台构建（需明确说明）。

### 6.6 测试编写的既有模式

- DbContext 单测：`new PimDbContext(new DbContextOptionsBuilder<PimDbContext>().UseInMemoryDatabase(Guid.NewGuid().ToString()).Options)`；模块实体需先 `PimDbContext.RegisterModuleAssembly(typeof(XxxEntity).Assembly)`。
- 服务层测试：Fake 实现 `ICurrentUserService`（两个属性 `UserId`/`Role`）。
- API E2E：`WebApplicationFactory<Program>` + `WithWebHostBuilder(b => b.UseSetting("DisableHangfire","true").UseSetting("GitHub:Repo","invalid/invalid-test-repo-xyz").ConfigureServices(...替换 InMemory...))`，参考 `AdminEndpointsE2ETests`。
- **测试命名空间绝不能叫 `Pim.UnitTests.Infrastructure`**（遮蔽生产命名空间）。
