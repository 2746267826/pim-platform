# PIM-046 | Mobile | 一般 | 并发同 BatchId 触发 mobile_app_catalog 唯一键冲突 23505

- 描述：`/usage/events` 并发同 `batchId` 时，`MobileUsageIngestService.UpsertAppAsync` 无行级锁，`MobileAppCatalog` `IX_mobile_app_catalog_user_id_device_id_package_name` 并发插入触发 `23505 duplicate key`，虽经 `strategy.ExecuteAsync` + `BuildPersistedResult` 恢复为同一 `ItemResults`，但日志 `ERROR SaveChangesFailed 23505` 且 `AcceptedCount` 与 `ItemResults` 数量不一致（`batch_id final-v1-batch-2` `AcceptedCount=2` 但 `ItemResults` 3条均 `accepted`）。
- 复现：
  ```bash
  API=http://127.0.0.1:15733
  TOKEN_A=$(cat /tmp/token_s1a.txt)
  cat > /tmp/payload_conc.json <<'JSON'
  {"deviceId":"session1-device-A","clientBatchId":"idem-test-batch-003","sourceWindowStartUtc":"2026-09-20T12:00:00Z","sourceWindowEndUtc":"2026-09-20T13:00:00Z","apps":[{"packageName":"com.test.conc3","displayName":"Conc3","versionName":"1.0","versionCode":1,"isSystemApp":false,"categoryName":"test","installerPackageName":"com.android.vending","firstInstallTimeUtc":"2026-01-01T00:00:00Z","lastUpdateTimeUtc":"2026-06-01T00:00:00Z","rawJson":"{}"}],"events":[{"packageName":"com.test.conc3","eventType":"MOVE_TO_FOREGROUND","eventTimestampUtc":"2026-09-20T12:05:00Z","className":"Main","collectedAtUtc":"2026-09-20T12:06:00Z","rawJson":"{}"},{"packageName":"com.test.conc3","eventType":"MOVE_TO_BACKGROUND","eventTimestampUtc":"2026-09-20T12:25:00Z","className":"Main","collectedAtUtc":"2026-09-20T12:26:00Z","rawJson":"{}"}],"fallbackSummaries":[]}
  JSON
  curl -s -X POST $API/api/v1/mobile/usage/events -H "Authorization: Bearer $TOKEN_A" -H "Content-Type: application/json" -d @/tmp/payload_conc.json > /tmp/c1.json &
  curl -s -X POST $API/api/v1/mobile/usage/events -H "Authorization: Bearer $TOKEN_A" -H "Content-Type: application/json" -d @/tmp/payload_conc.json > /tmp/c2.json & wait
  cat /tmp/c1.json | python3 -m json.tool | grep -A2 acceptedCount
  cat /tmp/api_session1_15733.log | grep "23505.*mobile_app_catalog" | tail -n 1
  PGPASSWORD=62f0a50bb963bb648f8e400399def95a psql -h 127.0.0.1 -p 5432 -U opencode -d pim_test -c "SELECT accepted_count, error_json FROM mobile_sync_batches WHERE batch_id='idem-test-batch-003';"
  # 两个并发均 200，但日志一次 DbUpdateException，需靠重试才幂等
  ```
- 预期：并发同 `batchId` 无 `ERROR`，直接返回幂等 `skipped/accepted`，且 `AcceptedCount==ItemResults accepted`。
- 实际：一次 `ERROR 23505`，`AcceptedCount=2` 与 `ItemResults 3×accepted` 不一致，依赖异常重试才收敛。
- 证据：`evidence/api/session1/concurrent_error.log`（`23505 duplicate key value violates unique constraint "IX_mobile_app_catalog_user_id_device_id_package_name"`）、`evidence/api/session1/usage_idem_req2.json`、`src/modules/Pim.Module.Mobile/Services/MobileUsageIngestService.cs:154-201`。
