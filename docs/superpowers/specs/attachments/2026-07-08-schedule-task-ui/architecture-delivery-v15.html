技术架构与交付治理：共享核心，多轨并行，阶段验证

实现时必须在独立新分支工作，适合用 goal 模式追踪长目标，并用多子代理按轨道同步推进。每个里程碑都要 commit、构建、测试，并在合适阶段通过 GA/GitHub Actions 验证。

错误处理与测试

不可省略
1
确认请求幂等重复同步、重复点击、网络重试不会重复写回或重复删除。
2
Graph token 与权限异常设备代码过期、刷新失败、权限不足时清楚提示并可重连。
3
冲突和审计补偿写回失败要保留待处理状态，不丢 before/after 和批次日志。
4
端侧在线边界采集可缓存；事实改动、审计确认、Outlook 写回必须在线。
5
构建与 GA 验证本地 `dotnet test Pim.sln`、`npm --prefix src/client-web run build`，再用 GA 验证主构建。
