# WIN-003 | client-windows/DaemonHeartbeat+PlannedOffline | 一般 | 上报服务无独立异常处理依赖外部兜底
- 描述：`DaemonHeartbeatReporter.ReportAsync` 与 `PlannedOfflineReporter.ReportAsync` 为透传封装，未做任何异常处理或日志。虽 `App.RunHeartbeatLoopAsync` 有 catch，但其他调用点（如 `TryReportPlannedOffline` 锁内 `Task.Run`）仅宽泛捕获，若未来新增调用方忘记 catch 即为未处理异常。
- 位置：src/client-windows/Pim.Client.Core/Services/DaemonHeartbeatReporter.cs:16-19; src/client-windows/Pim.Client.Core/Services/PlannedOfflineReporter.cs:14-17
- 问题：
  ```csharp
  public async Task ReportAsync(DaemonHeartbeatRequest heartbeat, CancellationToken ct = default)
  {
      await _api.PostAsync<object>("daemon/heartbeat", heartbeat, ct); // 无 try/catch
  }
  public async Task ReportAsync(PlannedOfflineRequest request, CancellationToken ct = default)
  {
      await _api.PostAsync<object>("daemon/planned-offline", request, ct); // 无 try/catch
  }
  ```
- 风险：服务层职责不完整，异常处理责任外移；新增调用路径易遗漏，导致后台任务崩溃或关机上报丢失。
