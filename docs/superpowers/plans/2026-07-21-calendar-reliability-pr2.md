# Calendar Reliability PR2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 PR2：在统一 Event 模型上实现原生与 Outlook 共享字段、Graph 无损保留和双向映射、统一编辑器与写回确认，并通过验证创建 PR。

**Architecture:** 保持唯一的 `EventEntity`、`EventResponse` 和 `EventEditorDialog`。实体使用兼容性 JSONB 列保存集合/结构化字段，API 暴露强类型对象；Outlook 只增加来源、绑定和同步元数据。Graph 完整属性包在映射边界保存到私有 `ExternalMetadataJson`，普通 API 只返回脱敏摘要。Outlook 的预览/确认/ETag 操作继续使用写回命令端点，但草稿字段、响应模型和编辑器与原生日程共用，不建立第二套事件模型。

**Tech Stack:** .NET 8, EF Core/Npgsql, PostgreSQL jsonb, System.Text.Json, HtmlSanitizer, Microsoft Graph REST, React 19, TypeScript, TanStack Query, Tiptap, DOMPurify, node:test, JSDOM, Playwright.

---

## Scope Decisions

- 保留 legacy `events.organizer` 字符串列；新增 `organizer_json`，迁移回填后所有新代码优先使用结构化列。PR2 不删除旧列。
- `categories`、`attendees`、`attachment_references` 在实体中使用规范 JSON 字符串映射到 jsonb；DTO 使用强类型集合。
- `CreateEventRequest`、`UpdateEventRequest`、`OutlookEventDraft` 的通用字段必须保持同名、同类型、同校验语义，并由契约测试防止漂移。
- `EventResponse` 不再返回 `ExternalMetadataJson`；改为返回 `OutlookAdditionalInfoDto?`。原始 Graph JSON 不通过普通事件或冲突响应下发。
- Graph `body.content` 先复制到 `ExternalMetadataJson.sourceSnapshot.body`，再生成安全规范化的 `Description`。
- Graph 特有的 `responseRequested`、`allowNewTimeProposals`、`hideAttendees` 和扩展属性只读保留，不写入 Graph PATCH。
- Organizer、Outlook `webLink`、远端会议 join URL 和 Outlook 附件在 Outlook 来源事件中只读；同名字段仍属于统一 Event 模型，原生日程可编辑。
- 附件二进制复制/上传不在 PR2；PIM 文件引用可编辑，Outlook 附件元数据可读取并通过服务端代理下载。
- PR3 的系列主事件、occurrence 生成和重复规则编辑不在本计划；PR2 只显示现有重复规则摘要。
- 仓库基线全局 lint 已有 18 errors/23 warnings。PR2 必须执行全局 lint 并记录基线，同时对全部本次修改的前端文件执行定向 lint，要求 0 error、0 新 warning。
