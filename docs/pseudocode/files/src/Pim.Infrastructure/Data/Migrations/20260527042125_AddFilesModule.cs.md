## 函数级结构化伪代码

### AddFilesModule
#### `void Up(MigrationBuilder migrationBuilder)`
- 输入：迁移构建器
- 输出：无
- 副作用：创建 7 张表、大量索引与跨表外键（含版本循环引用约束）
- 步骤：
  1. 建 `file_providers`：用户绑定 Nextcloud 等提供商（base_url、凭据密文、status 默认 pending）
  2. 建 `file_ai_results`：按文件版本的摘要/标签 jsonb/语言敏感度/模型与证据 chunk ids
  3. 建 `file_chunks`：分块文本、hash、偏移、可选 qdrant_point_id
  4. 建 `file_index_jobs`：索引流水线状态/stage 默认 metadata、attempt、错误与起止时间
  5. 建 `file_items`：外部文件树节点，FK → `file_providers` Cascade
  6. 建 `file_suggestions`：建议类型/置信度 0–1 检查约束，FK → `file_items` Cascade
  7. 建 `file_versions`：版本历史，AK `(file_item_id, id)`，FK → `file_items` Cascade
  8. 建唯一/过滤索引：如 provider 四元组唯一、chunk 索引唯一、qdrant 非空唯一、current 版本过滤唯一等
  9. 补 FK：ai_results/chunks/index_jobs 指向 items 与 versions；items 当前版本指向 versions（Restrict）
- 分支与异常：SQL 失败中止迁移
- 调用：`CreateTable` / `CreateIndex` / `AddForeignKey`

#### `void Down(MigrationBuilder migrationBuilder)`
- 输入：迁移构建器
- 输出：无
- 副作用：先断 `file_versions`→`file_items` 外键，再 Drop 业务表与 providers/versions
- 步骤：
  1. DropForeignKey `FK_file_versions_file_items_file_item_id`
  2. Drop `file_ai_results`、`file_chunks`、`file_index_jobs`、`file_suggestions`、`file_items`、`file_providers`、`file_versions`
- 分支与异常：依赖残留则失败
- 调用：`DropForeignKey` / `DropTable`
