# 阶段二操作卡（REQ-24）

> 工单 WO-ANDROID-KEEPALIVE-20260923 v1.3 · 阶段二交付物
> 需求方原话为「三步操作卡」，工单按**可执行粒度**拆为四步（AC-24.1）。
> 每一步都写明「点什么」与「预期看到什么」，缺任一步或缺预期现象即视为未交付（AC-24.2）。

## 前置

- 安装包：由开发方提供的 `app-debug.apk`（或发版包）
- 设备：OPPO PLG110（ColorOS 17 / Android 17）或 OPD2409（Android 16）
- 建议在**同一个晚上**集中完成四步（工单第 8 节第 3 条 / D33）

---

## 第 1 步：装包

| 项 | 内容 |
|---|---|
| 点什么 | 用数据线连接手机，执行 `adb install -r app-debug.apk`；或直接把 apk 传到手机点击安装 |
| 预期看到什么 | 安装完成无报错；桌面出现 **PIM** 图标；首次打开能进入应用并完成登录 |

**装完后立刻可核对的一件事**：打开「设置 → 应用管理 → PIM → 特殊权限」，
应能看到 **「闹钟和提醒」** 这一项（说明权限已随包声明，REQ-14 双声明生效）。

---

## 第 2 步：打开「闹钟和提醒」权限

| 项 | 内容 |
|---|---|
| 点什么 | 打开 PIM → **设置** → 找到 **「保活与诊断」** 分区 → 点「当前状态」里的 **「闹钟和提醒权限」** 那一行（显示「未授权」时该行可点） |
| 预期看到什么 | ① 系统直接跳到「闹钟和提醒」权限页；② 把它打开后返回 PIM；③ 「保活与诊断」里该行变为 **「已授权」**，且「登记状态」显示 **「已登记」** |

**若没有自动跳转**：页面会显示一段文字路径（「设置 → 应用管理 → PIM → 特殊权限 →『闹钟和提醒』→ 允许」），
按它手动前往即可（这正是 AC-23.4 的回退设计）。

**若这一行本来就显示「已授权」**：说明 ColorOS 按 `USE_EXACT_ALARM` 安装即授予了 ——
请把这一现象记下来，这正是 REQ-25 需要确认的三项之一。

---

## 第 3 步：手动强停验证（闹钟是否被系统清空）

| 项 | 内容 |
|---|---|
| 点什么 | ① 确认「保活与诊断」显示「已登记」；② 进入系统「设置 → 应用管理 → PIM → 强行停止」，点确定；③ 重新打开 PIM |
| 预期看到什么 | ① 强停后重开：状态页**顶部出现红点**，文案含「检测到应用被强行停止」或「系统清空了保活闹钟」；② 「保活与诊断 → 登记状态」重新变为「已登记」（应用已自动重建闹钟） |

**这一步同时验证两条**：REQ-2 的强停判定（阶段一能力）与 AC-21.1 的「闹钟被清空」红点。
按平台依据 §4，强停会清空该应用全部闹钟，因此「重建」是必须发生的行为（AC-15.4 同源）。

---

## 第 4 步：按引导修改系统设置

| 项 | 内容 |
|---|---|
| 点什么 | 进 **设置 → 保活与诊断 → 系统设置引导**（状态页存活区块里的「系统设置引导」按钮是同一个页面的第二个入口）。逐项处理：<br>① **可自动检测**三项：闹钟和提醒权限 / 电池优化 / 待机分区 —— 看它显示的当前状态，未就绪的点「打开设置」；<br>② **需要手动确认**四项：自启动 / 允许后台运行 / 应用速冻 / 睡眠待机优化 —— 按每项下方的文字路径去系统里改，改完勾选 **「我已完成」** |
| 预期看到什么 | ① 可检测项显示系统**真实**读数（如电池优化显示「已排除（不优化）」）；② 手动项勾选后状态变为 **「已标记完成」**，退出页面再进来**仍然是「已标记完成」**（AC-23.3 记住了）；③ 若某个跳转打不开，页面**不崩溃**，顶部出现「无法自动打开该设置页」并保留文字路径 |

**建议的 ColorOS 目标值**（依据 android-平台依据 §6）：自启动=允许、允许后台运行=允许、
应用速冻=关闭、睡眠待机优化=不优化、电池优化=不优化。

---

## 四步做完后：给需求方的观察建议

1. **保持采集开启**（设置 → 持续采集 打开），否则闹钟会按 REQ-20 只记台账不采集 —— 这是设计行为，不是故障。
2. 观察 **1–2 天**，然后看两个地方：
   - 手机端：**设置 → 保活与诊断** 里的「最近一次叫醒」是否持续更新（应约每 30 分钟一次）；
   - Web 端：**手机记录 → 设备存活** 页的覆盖率与最长静默，与阶段一基线对比。
3. 若出现「最近一次叫醒」长时间不更新，**先看状态页顶部有没有红点** —— 红点会直接说明原因
   （权限被撤销 / 闹钟被清空 / 检测到强停 / 连续拉起失败）。

---

## 已知的非目标行为（避免误判为故障）

| 现象 | 说明 |
|---|---|
| 暂停采集后叫醒不再拉起服务 | REQ-20 明确要求：暂停时只写台账、不拉起、不采集（AC-20.1） |
| 手动采集期间跳过某次叫醒 | REQ-20 / AC-20.2：避免打断用户正在进行的会话 |
| 状态栏**没有**闹钟图标 | 这是设计要求（只用 `setExactAndAllowWhileIdle`，不用 `setAlarmClock`，AC-15.3） |
| 通知栏有**两条**常驻通知 | 一条是采集服务、一条是保活状态，AC-19.2 要求两者并存互不覆盖 |
