# Android 客户端轻量补完总设计

取代旧 Android Completion / Reliability 设计与 Phase 1/2/3 计划。本文为总设计，后续按阶段各出一份短计划。

---

## 一、目标与原则

1. 保留完整用户功能（今日、轨迹、日程、状态、设置、采集、同步、权限、诊断、服务端页面复用），大幅减少内部机制和文档负担。
2. 现有代码能复用就不重构。Task 0–3 已有实现按其复用决策保留或替换，不因投入而强制保留。
3. 用户看得到事实：数据不静默丢失、token 不跨服务器、迁移不破坏数据。完成标准以"关键路径可靠"为准，不追求穷举覆盖。
4. 放弃 lease 表、broker、generation/CAS、多个 coordinator、多表同步历史、独立 ProbeRunner、复杂并发 store。能用单 Mutex + fail-closed 解决的就不引入新机制。

---

## 二、完整功能范围（10 类）

### 2.1 今日
- 作为默认标签显示真实地图、轨迹线、停留点、当日距离、完整度、手机使用摘要、当前采集策略、下次定位时间和传输状态。
- 标明服务端数据的生成或更新时间，避免把旧数据当成实时数据。
- 明确区分无数据、待上传、未开始、错误四种状态。
- 地图和内容区域使用服务端 embed WebUI，仅通过当前服务器页面获取。

### 2.2 轨迹
- 按时间范围和质量筛选。地图展示轨迹线。
- 片段时间线（可展开）、片段详情、原始坐标点分页列表。
- 明确空状态和错误状态。

### 2.3 日程
- 显示当前项、下一项、近期日程（-6h ~ +7d）。
- 策略选择对采集频率的影响提示。
- 缓存来源带时间戳，标注新鲜度。
- 真实空状态（无日程）、错误与重试提示。

### 2.4 状态
- 总体结论（正常/需注意/异常）。
- 详细可操作问题列表（如"定位权限被关闭，点击修复"）。
- 传输进度（队列中/上传中/已完成/失败）、待传数量、服务端确认数量、上次成功和下次尝试时间。
- 采集状态、权限状态、网络连接状态、诊断摘要。
- 按钮执行对应动作（如打开系统设置、触发同步）。手动同步后即时刷新页面。

### 2.5 设置
- 服务器地址输入与连接测试。
- 登录/登出。
- 三档采集预设（省电/标准/高精度）。
- 有限高级参数（常规采集间隔、日程低频间隔、运动观察间隔、恢复距离、精度阈值、海拔等待时间），全部限制在安全范围内。
- 网络偏好（仅非流量网络 / 任意网络）。
- 持续采集开关，默认关闭，由用户明确开启。
- 系统权限入口（定位、通知、电池优化）。
- 详细日志开关与日志保留天数。
- 恢复采集、网络和日志默认值，不清空服务器地址或登录信息。

### 2.6 采集
- 后台持续定位，系统杀死后通过恢复入口重启。
- 精度过滤（丢弃低精度点）。
- 海拔采集等待稳定后再记录。
- 日程已知时段切换低频模式。
- 运动状态观察（静止/步行/车载）调整采集间隔。
- 距离恢复：处于日程低频模式时，移动超过恢复阈值后恢复普通采集频率。
- 通知栏显示采集状态和操作（暂停/恢复、立即同步、打开状态页）。
- 采集意图跨断网、退出、重启保留。

### 2.7 同步
- 触发方式：手动（按钮）、前台（应用启动/恢复时）、后台（周期 WorkManager）、网络恢复后由 WorkManager 约束继续执行。
- 重复防护：WorkManager unique work 保证同一时间只有一个同步任务。
- 自动重试：网络错误、超时、5xx 自动排队等待下次周期或手动触发。
- 仅非流量网络偏好下，手动同步可由用户确认一次使用流量网络，不永久修改偏好。
- 队列/阶段/结果可见：状态页显示 pending 数量、uploading 进度、confirmed 成功数、rejected 失败原因。
- 逐项服务端确认：每发送一项等待服务端回 confirmation——confirmed 则删除或归档，rejected 则原行保留并记录原因。
- 永久拒绝（如格式错误、版本不兼容）使用业务行现有同步状态和错误字段保留事实，不再重复上传。

### 2.8 权限与恢复
- 六项权限/设置：通知、精确定位、后台定位、使用情况访问、活动识别、电池优化豁免状态与入口。
- 开机广播（BOOT_COMPLETED）调用恢复入口。
- 升级后（Package Replaced）调用恢复入口。
- 进程被杀死后，下次用户打开应用或开机时恢复采集意图。
- 状态页显示具体的阻塞原因（如"后台定位权限未授予→点击前往设置"）。

### 2.9 诊断
- 本地日志：按级别和标签记录，仅写入应用专属存储。日志不进入业务队列表。
- 保留策略：按天数（默认 7 天）滚动删除；详细日志模式开启 24 小时后自动关闭。
- ZIP 打包：包含当前状态、精简同步历史、日志、相关数据库计数和必要诊断事实，不包含 token/密码。
- 导出原始坐标前明确警告并要求用户确认；未确认时不包含原始坐标。
- 清除诊断数据不影响业务数据。
- 导出前检查磁盘空间，导出失败时删除不完整 ZIP。

### 2.10 服务端页面复用
- 今日与轨迹复用服务端 WebUI 的数据展示能力，并提供适合 Android 嵌入的页面入口。
- 仅当前配置服务器下的页面拥有 Android 登录 token 传递能力和原生交互桥。
- IP、局域网地址、非标准端口、HTTP 均可使用（HTTP 页面显示未加密警告横幅）。
- 地图 SDK / CDN 等普通子资源可正常加载，但不会获得 Android token 或原生 bridge。
- 非当前服务器外部网页不获取 token，不注入 bridge，不做登录穿透。
- refresh token 永不进入 WebView；网页只按需获得当前服务器的短期 access token。
- WebView 错误不显示白屏——显示原生错误页面，包含错误详情和重试按钮。

## 三、轻量技术基线

以下为职责级描述，不强制创建同名类。现有功能等价即可保留。

1. **一个 SyncWorker**：手动、前台、周期触发均进入同一同步入口。WorkManager 的 unique work 天然防重复。通过 WorkInfo 查询状态，配合精简的同步历史表展示结果。
2. **表结构**：保留现有业务队列表。最多增加一张精简同步历史表。永久拒绝复用业务行的同步状态和错误字段。不创建 lease、dead-letter、scheduler cache 等多表。
3. **日程缓存**：一次 API 请求后存为带获取时间的单份 JSON。页面进入时尝试刷新；刷新失败保留旧缓存并标记其时间，不把失败伪装成空结果。
4. **StatusRepository**：汇总 Room 状态、WorkInfo、网络状态、采集意图、服务状态、权限状态、最近连接检查和日志状态。一个简单函数生成问题列表，不拆多层事实/评估/规划器。
5. **一个认证仓库**：EncryptedSharedPreferences 存 token，标记所属服务器 URL。进程内 Mutex 保证 refresh 不并发。401 最多 refresh 一次并重试一次，失败后要求重新登录。不跨服务器发送 token。不引入持久 generation/CAS、多重 tombstone、双回滚证明或穷举线程交错测试。
6. **连接检查**：3–4 步——地址解析与网络/TLS、服务可达、API 版本与登录、Web 页面可达。保存最近结果和检查时间。不强制独立 ProbeRunner 或复杂并发 store。
7. **一个 ensureRunningState 恢复入口**：由 Application.onCreate、BOOT_COMPLETED 广播、PACKAGE_REPLACED 广播调用。职责：唯一周期 work 注册、旧 work 清理、采集意图恢复。
8. **原生 vs Web**：今日、轨迹 → embed WebUI；日程、状态、设置、诊断 → 原生页面。WebView 为通用组件，按服务器配置注入 token 和 bridge。

## 四、交付阶段

### 阶段 1：运行与可诊断

| 内容 | 说明 |
|------|------|
| 状态页面 | 读取 Room/WorkInfo/服务/权限/采集意图/probe 给出问题和结论 |
| 设置页面 | 地址/连接测试/登录登出/三档预设/网络偏好/持续采集/权限入口/日志/默认还原 |
| 采集收口 | 后台定位、精度筛选、海拔等待、低频模式、运动观察、距离恢复、通知控制 |
| 采集恢复 | ensureRunningState、BOOT_COMPLETED、PACKAGE_REPLACED、开机恢复尝试 |
| 同步收口 | SyncWorker、unique work、逐项确认、永久拒绝保留、重试、周期调度 |
| 权限管理 | 六项权限/设置引导、阻塞原因显示 |
| 诊断 | 本地日志、保留策略、ZIP 导出、坐标警告、排除凭据、清除不影响业务 |
| 连接检查 | 3–4 步检测、结果缓存 |

场景验收：
- 首次安装：配置服务器、授予权限并由用户开启持续采集后，采集和同步正常运行
- 强制停止应用 → 再次打开：采集意图恢复、同步继续
- 关闭定位 → 状态页显示具体阻塞 → 点击跳转系统设置 → 恢复后采集重启
- 开机后：系统允许时恢复采集；系统阻止时记录原因并在状态页给出操作
- 日志导出 ZIP 不包含 token
- 选择包含原始坐标时必须先出现明确确认；取消确认后 ZIP 不含原始坐标
- 设置"恢复默认"后采集、网络和日志参数恢复默认，服务器地址与登录信息保持不变

### 阶段 2：今日与轨迹

| 内容 | 说明 |
|------|------|
| 通用 WebView 组件 | 注入 token、bridge；HTTP 显示未加密警告；错误显示原生错误页 |
| 今日 embed | 加载 WebUI，传递登录上下文、采集和同步状态摘要 |
| 轨迹 embed | 加载 WebUI，传递登录上下文；时间和质量筛选由服务端页面统一实现 |
| 地图 SDK 初始化 | 复用 WebUI 自有地图，不必在原生侧重复集成 |
| 原生本地状态层 | 今日——无数据/待上传/错误；轨迹——空/错误 |
| 同步后刷新 | 同步完成后主动 reload WebView |

场景验收：
- 首页显示真实地图和轨迹线，数据与 Web 端一致
- 使用 IP 地址和 HTTP 连接→页面正常加载，横幅显示"连接未加密"
- 断网时打开今日→显示原生无数据/错误页，非白屏
- 轨迹按日期筛选后地图和列表正确更新
- 同步完成后今日页面自动刷新反映最新数据
- 加载非服务器地址的 URL→不注入 token，界面隔离

### 阶段 3：日程与策略

| 内容 | 说明 |
|------|------|
| 日程 API 查询 | now-6h ~ now+7d，带时间戳 JSON 缓存 |
| 原生日程页面 | 当前项、下一项、列表视图；空/过期/错误状态 |
| 策略影响提示 | 日程中显示当前低频策略、触发原因和恢复条件 |
| 采集低频模式 | 日程已知事件时段降低采集频率 |
| 运动状态观察完善 | 静止、步行、车载状态使用不同的有界采集间隔 |
| 距离恢复增强 | 日程低频模式中移动超过阈值后恢复普通采集频率 |
| 策略状态与历史 | 状态页显示当前生效策略和切换记录 |

场景验收：
- 服务端有日程→Android 正确展示当前、下一项和策略影响
- 服务端无日程→页面显示"当前无日程安排"，非空列表或错误
- 断网→显示缓存日程（标注"可能过期"），联网后自动刷新
- 日程活动时段采集频率降低，状态页和日志可见当前原因
- 运动状态变化后采集间隔按配置调整，不直接清除采集意图
- 日程低频期间移动超过阈值→距离恢复触发→回到普通采集频率

## 五、数据流与错误规则

### 5.1 主数据流

```
采集 → Room pending 表 → SyncWorker（唯一实例）→ 逐项 HTTP POST → 服务端确认
  ├─ confirmed → 删除/归档
  ├─ rejected → 原行保留，记录永久拒绝状态和原因
  └─ 未确认（网络/超时/5xx）→ 继续 pending，下次重试
```

- 日志写本地文件，不进入业务队列表。
- 状态页只读取 Room、WorkInfo、ConnectivityManager 等事实，不因按钮点击后盲目显示成功。

### 5.2 日程数据流

```
API 请求 → 带获取时间的 JSON 缓存 → 页面展示 + 策略消耗
网络失败 → 保留旧缓存（标注可能过期）→ 页面显示缓存新鲜度
```

### 5.3 错误规则

| 场景 | 行为 |
|------|------|
| 网络不可用 / 超时 | 数据保留在 pending 表，下次重试 |
| HTTP 429 / 5xx | 保留数据，指数退避后重试 |
| 登录过期（401） | 停止上传，保留采集和队列；触发 refresh；refresh 失败则报错 |
| 权限缺失 | 保留采集意图，状态页提示具体缺失 |
| 服务器地址错误 | 不上传（连接检查不通过），状态页提示 |
| 日程 API 错误 | 显示原生错误状态，不清空缓存 |
| WebView 加载错误 | 显示原生错误页（含详情和重试），不显示白屏 |
| Room 迁移失败 | 保留旧数据库，上报错误，不 destructive rebuild |
| ZIP 导出失败 | 删除不完整 ZIP 文件 |
| 用户取消操作 | 仅取消当前任务，不伪装成业务失败 |

### 5.4 持久状态清单

持久化：待传业务行（含永久拒绝事实）、同步历史精简表、日程缓存 JSON（含获取时间）、最近连接检查与时间、EncryptedSharedPreferences（token + 所属服务器）、普通设置、App 专属日志文件、采集意图标志。

不由应用重复持久化：WorkInfo（WorkManager 自动维护）、页面展开和加载状态、实时运动状态、权限状态（每次检查当前权限）。

## 六、测试与审查

### 6.1 严格自动测试（必须通过才能交付）

| 测试 | 范围 |
|------|------|
| 逐项确认 / 不丢数据 | Mock 服务端确认：confirmed 删除、rejected 保留原因、未确认继续 pending；重新运行同步后仍能继续处理保留数据 |
| Room 迁移 | 从当前已发布版本升级到新版本，业务数据、设置和诊断边界保持正确 |
| Token 不跨服务器 | 切换服务器后旧 token 不被发送；新服务器需重新登录 |
| 同步唯一 | 多个触发入口都提交同一个 unique work，观察到的活动同步不重复 |
| ZIP 无凭据 | 导出 ZIP 不包含 token、密码 |

### 6.2 关键路径自动测试

设置 → 连接检查 → 登录 → 同步（含重试与 reject 处理） → 状态页准确反映 → 日程缓存与策略消耗 → WebView 加载与错误页 → 权限动作生效

### 6.3 普通功能测试

每类功能 1 个成功路径测试 + 1–2 个关键失败测试（如网络错误、空数据、权限拒绝）。不要求 SharedPreferences 双失败、所有线程交错、毫秒边界组合、源码字符串穷举、逐任务双重评审、大型证据矩阵。

### 6.4 策略

每阶段一次完整自动测试运行、一次模拟器验收（覆盖该阶段场景验收清单）、一次代码审查。真实 bug（无论覆盖率高低）仍需回归测试。

## 七、Task 0–3 复用决策

| Task | 决策 | 理由 |
|------|------|------|
| Task 0（覆盖率/矩阵） | 历史参考，不继续维护 | 新测试策略替代 |
| Task 1（测试环境 + Room v3 schema） | 保留 | 环境无需重做；schema 已上线 |
| Task 1（源码字符串测试） | 只保留行为有价值部分 | 文案测试价值低 |
| Task 2（item-level ack + capability） | 完整保留 | 核心同步机制，已验证 |
| Task 3（endpoint resolver） | 保留 | 稳定可用 |
| Task 3（refresh + server token isolation） | 保留行为，允许简化实现 | 单 Mutex + EncryptedSharedPreferences 够用，去掉 generation/CAS |
| Task 3（probe） | 保留失败分类，减少阶段/runner/并发机制 | 简单函数 + 时间戳结果即可 |
| Task 3（generation / CAS / tombstone / 双回滚） | 重新评估，能用单 Mutex + fail-closed 完成则删除 | 已有非提交成果先备份再审查，不默认全留、不从零重写 |
| Task 3 当前未提交成果 | 先备份，再按用户行为逐项审查 | 避免丢失，也避免强制保留不需要的机制 |
